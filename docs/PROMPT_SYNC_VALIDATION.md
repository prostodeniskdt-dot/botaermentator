# Проверка синхронизации промптов

Дата: 25 октября 2026 (Москва). Исходная версия: main, 9f4a19e.
Пользователь предоставил полные тексты трёх агентов и согласовал план реализации.
Фактические настройки панели Timeweb не прочитаны и не изменены. Деплой не выполнялся.

## Реализовано

- Канонические полные тексты — app/prompts/approved; версия 2026-10-25.1, SHA-256 в manifest.json.
  docs/TIMEWEB_AGENT_PROMPTS.md содержит эти же тексты и генерируется sync_prompt_docs.py.
  Короткие файлы app/prompts/*.md содержат только контракт запроса.
- Полный локальный источник остаётся безопасным default. Режим panel включается явно,
  с совпадающим идентификатором набора; это декларация оператора, не доказательство
  состояния панели. Пустые/отсутствующие обязательные файлы и повреждённые локальные копии
  не заменяются пустой строкой. Нет автоматического повтора генерации при смене источника.
- JSON агентов 1/2 проверяется строго: обязательность, типы, отсутствие лишних полей,
  диапазон уверенности, защитные флаги и соответствие relation/include_previous_context.
  Предпочтительные категории не превращены в закрытый enum. Исправляющий запрос при
  ошибке JSON, fail-closed фильтра и консервативный standalone-fallback контекста сохранены.
- Только related может использовать переписанный вопрос с прежними параметрами, историю
  и резюме. Профиль и уровень пользователя загружаются независимо от связи тем.
  При ambiguous эксперт получает исходный вопрос и инструкцию уточнить недостающие сведения;
  фильтр получает признак неоднозначного продолжения, без старых параметров и обхода защит.
  Эти ответы не попадают в FAQ и не предлагают платное расширение уточняющего вопроса.
- Для личного диалога граница темы хранится через существующий context_relation после
  допуска фильтра. Недопустимый запрос не переключает тему; ошибка генерации после допуска
  не возвращает прежнюю тему. Выборка истории ограничивается последней границей.
  При совпадении timestamps исключаются другие строки на момент границы, чтобы случайно
  не захватить параметры прежней темы. Параллельные пользовательские чаты не добавлены.
- Резюме с подтверждённым происхождением хранится в существующем JSONB context_snapshot
  вместе с версией набора и topic_root_question_id. Резюме больше не объявляется
  установленными фактами. Для legacy-снимков без версии берётся только последняя
  известная пара вопрос/ответ, без потенциально смешанного session.summary. Это может
  потребовать повторного уточнения старых деталей, но не удаляет историю или профиль.
- Расширение использует снимок исходного ответа. Внутренняя метка expansion отделяет его
  от решения агента 2: расширение старого ответа не переключает текущую тему и не заменяет
  её резюме. Расширения текущей темы доступны в ограниченной истории. Новых значений
  relation, принимаемых от ИИ, нет. Резервы, стоимость и повторные клики сохранены.
- Проверка ссылок рекомендаций учитывает регистр, Telegram aliases и настроенные URL,
  а также границу имени бота; применяется и к свежим, и к кэшированным ответам.
- PROMPT_VERSION=5; ключ FAQ дополнительно включает набор и источник промптов. Существующие
  поля режима, уровня и KB сохранены. Изменения схемы PostgreSQL и новые миграции не нужны.

## Автоматическая проверка

```bash
ruff check .
ruff format --check .
python scripts/sync_prompt_docs.py --check
TEST_DATABASE_URL=postgresql+asyncpg://test_user@127.0.0.1:55432/test_db pytest
```

Тесты JSON проверяют пропуск каждого поля, неверные типы/связи/флаги, retry и fallback.
Тесты состава запроса проверяют оба источника, все уровни и оба режима, сохранение
запроса подборки публикаций и отсутствие прежнего контекста при ambiguous.
Интеграционные тесты PostgreSQL проверяют несколько последовательных тем, сохранение
профиля/истории, ошибку генерации, расширение старого ответа и рекомендации при cache hit.
Существующие проверки кредитов, рестарта, доставки нескольких частей и миграций сохранены.

Результат проверки на Python 3.12 и изолированной PostgreSQL 16.4: **238 passed**, без
пропусков. Ruff, проверка форматирования, синхронизации документа и git diff --check прошли.
Остаётся предупреждение зависимости Starlette TestClient об устаревшем API httpx.

Эти проверки не доказывают качество реального ответа модели или достоверность публикаций.
Не было платных вызовов Timeweb или Telegram production API.

поиска. Не объявлять содержимое панели проверенным только по версии в переменной окружения.
Полные тексты не редактировать ради прохождения модельной оценки без нового согласования.
